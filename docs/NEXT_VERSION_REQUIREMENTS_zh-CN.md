## v1.9.11-codex.7 实施记录

### 1. 队列已有文件时仍支持拖拽追加上传

- 记录日期：2026-10-26。状态：已实现；事件路由回归及队列接口检查通过，实际浏览器拖拽验收待完成。
- 用户反馈：队列里已有一个文件后，再将文件拖到上传区域无法继续上传，而是在浏览器里打开该文件。
- 期望行为：队列非空时，上传区域仍可接收拖入的文件，将新文件追加到现有队列，保留原有文件；阻止此次拖放触发浏览器直接打开文件或跳转页面。
- 验收要点：先上传一个 PDF，再向同一区域拖入一个或多个 PDF，均能追加到队列；队列已有多个文件时也能继续追加，空队列的拖拽上传仍正常。

### 2. Codex 模型与 effort 支持自动读取、下拉选择及手动填写

- 记录日期：2026-10-28。状态：已实现；自动目录、手动输入、模型切换联动和失败保留配置均已通过回归与接口检查。
- 通过用户选择的 Codex CLI 查询 `model/list`，读取模型 ID、显示名称、支持的推理强度及默认值；提供刷新入口，切换模型时联动 effort 选项。
- 模型与 effort 均保留手动填写。读取失败时保留现有值并提示，不清空配置，不替换用户填写的模型；未识别的新 ID 仍可手动使用。
- 下拉选项须取目录与翻译后端支持范围的交集。API 模型文档、Codex 客户端目录与账号实际调用权限要区分，不能硬编码一个通用列表冒充实时查询。
- 已实测本机内置 CLI `0.163.0` 的 `model/list` 成功，返回 8 个可见模型，含 `gpt-6.1-terra` 及各模型 effort；只读证据在本轮私人审查目录。界面复用原配置输入，提供可编辑下拉框和刷新入口。
- 已更新中英文模型说明，加入 GPT-6.1 Terra 的精确 ID 及官方来源。

### 本轮模型使用约定

修改、诊断和检查继续使用当前 Astra / max / 标准速度；仅验证翻译调用 `gpt-6-luna` / `max`，使用用户要求的 Fast 加速。不得把翻译模型设置用于切换当前开发聊天的模型或速度。

### 实施前先检查完整 PDF 并修复翻译问题

当用户明确要求开始修改这些需求时，必须按以下顺序进行：

1. 检查届时最新版本截至该时间点已翻译完成的所有完整 PDF，逐份检查全文，找出其中的翻译 bug；不能仅检查第一页或局部片段。用户于 2026-10-23 明确：只检查完整完成的任务，排除仅译第一页的测试任务和中途失败的任务。
2. 先修复检查发现的所有翻译 bug，并复核修复结果。
3. 上述问题全部修复后，再开始本文件所列功能需求的修改。

已检查最新版 .5.4 的 6 个完整任务，共 66 页原文；全文重译、结构核对与已发现问题的视觉复核记录保存在本地审查目录，不随公开代码或发行包分发。工作区根目录中三份暂停记录保留为历史检查点，不能当作当前开发状态。

### 翻译完成后显示翻译时间

在用户截图所示的“翻译预览 / PDF 队列”区域，翻译完成后也要保留翻译时间（耗时）的显示，不能只显示“已完成”。

### 实时预览保留原文页面与翻页逻辑

- 开始翻译前后，保持原有的上一页、下一页按钮及翻页逻辑不变。
- 预览从开始翻译时就保留原文的全部页面和页码顺序，尚未翻译完成的页面继续显示原文，仍可正常翻页浏览。
- 每当某一页翻译完成，实时用该页译文替换对应的原文页面，其余尚未完成的原文页面继续显示。
- 页面数量和可翻页范围不随翻译进度变化，不再采用“翻译好一页才显示一页”的方式。

### 翻译日志入口与历史记录

新增可查看翻译日志的按钮，能够回顾每次翻译任务，包括：

- 什么时间输入了哪篇文章。
- 什么时间开始翻译。
- 什么时间报错，以及对应的报错信息。
- 报错时翻译到了哪里，例如当时的页码、进度或处理阶段。
- 当时翻译缓存是否正常。
- 翻译成功的记录及其对应文章。

### 成功记录中的文章信息

翻译成功的历史记录应能识别对应文章，并简单补充文章作者、期刊和年份。

### 从历史记录下载原文与译文

- 可以在记录中直接下载已翻译文章和文章原文，使用软件保存在本地的对应文件。
- 文件被误删或清理后，保留对应历史记录，将缺失的文件显示为“已删除”。

### 管理本地缓存与文章文件

在日志或历史记录所在入口提供本地翻译缓存及已翻译文章的管理功能，允许用户清理软件本地储存的缓存或文件。

清理前提醒用户妥善保管已翻译文本，先保存所需文件，再删除软件本地储存的缓存或文件。

缓存和翻译记录管理不要求强行兼容旧版本。旧版本数据若无法兼容，无需为此额外实现兼容或迁移逻辑。
